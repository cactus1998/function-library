# 面試講稿

目標：讓使用者能在 2–5 分鐘內講清楚一個功能，並接得住追問。內容必須以實際程式碼為依據，不能虛構沒有實作的特性。

## 步驟

1. 讀取 `src/features/<slug>/` 下所有檔案（meta、元件、composables、測試）。沒有指定 slug 時，列出現有 features 讓使用者選。
2. 找出真正的技術重點：演算法、效能手法、狀態管理、型別設計、無障礙、錯誤處理、瀏覽器 API。
3. 寫入（或更新）`src/features/<slug>/NOTES.md`，使用下方模板。檔案已存在時，保留使用者手寫的內容，只更新過時的段落。
4. 發現程式碼有弱點（例如沒處理 race condition、沒有清理 listener）時，不要在講稿裡掩飾。把它寫進「已知限制」，並在回覆中建議修正方式。
5. 回覆使用者：一句話總結，加上 3 個最可能被追問的問題。

## NOTES.md 模板

```markdown
# <功能標題>

## 30 秒電梯簡報
<一段話：做了什麼、解決什麼問題、最亮的技術點>

## 問題背景
<為什麼需要這個功能；naive 做法會遇到什麼問題>

## 實作重點
- <重點 1：對應的檔案與函式，例如 `composables/useVirtualList.ts` 的 `visibleRange`>
- <重點 2>

## 設計決策與取捨
| 決策 | 替代方案 | 為什麼選這個 |
|------|----------|--------------|

## 複雜度 / 效能
<時間與空間複雜度、渲染次數、量測方式（如 Performance 面板、`performance.now()`）>

## 已知限制與可延伸方向
- <限制> — <怎麼改進>

## 面試官可能追問
**Q: <問題>**
A: <簡潔回答，必要時附程式碼片段>

（至少 5 題，涵蓋：原理、邊界情況、效能、測試方式、如果規模放大 10 倍怎麼辦）

## 相關知識點
<可順帶延伸的面試考點，例如 event loop、reflow/repaint、Vue reactivity 原理>
```

## 寫作原則

- 用使用者的語言（繁體中文），技術名詞保留英文原文。
- 回答要口語、可以直接講出口，避免教科書式長段落。
- 引用程式碼時標示檔案路徑，方便展示時直接打開。
